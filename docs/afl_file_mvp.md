# AFL++ и один гостевой файл

Этот документ описывает прежний режим `--mode fresh` для регрессионных проверок.
Основной режим теперь `warm`: Phase 1 выполняется один раз на кампанию.
Инструкция: [Фаззинг после retirement](afl_post_retirement_fork.md).

Реализация добавляет в TaintForge базовый цикл coverage-guided fuzzing. AFL++ создаёт мутации обычного файла на хосте. Отдельная попытка TaintForge помещает его содержимое в заданный гостевой файл и запускает исходный ELF через существующий M4-пайплайн. Карта переходов гостя возвращается AFL++, который решает, какие входы сохранить в очередь.

## Что происходит за одну попытку

1. `afl-fuzz` выбирает seed, изменяет его и записывает в свой файл `@@`. Он запускает нативный `tf-afl-bridge` один раз; далее работает классический forkserver AFL с дескрипторами 198/199. Хостовый bridge собран обычным `cc`, без инструментирования его собственного кода.
2. Forkserver создаёт пару сокетов, делает `fork()` и передаёт контроллеру серверный дескриптор через `SCM_RIGHTS`. Дочерний процесс отправляет длину и байты `@@`. На каждую попытку приходится отдельное соединение. У гостя нет этих дескрипторов и переменной `__AFL_SHM_ID`.
3. Контроллер создаёт `cases/00000000`, сохраняет `input`, запускает отдельный Python worker и ждёт его. Worker проверяет исходники, исполняемые ресурсы, bundle и снимок базового rootfs. Снимок относится к файловому дереву; это не снимок CPU.
4. Worker клонирует базовый rootfs, заменяет содержимое одного выбранного файла, копирует конфигурацию bundle и начинает новую сессию с `max_iterations=1`. Идентификатор попытки, ресурсы M4, observer и retirement проверяются прежним unified pipeline. Автоматическое исправление окружения в пределах одной мутации не выполняется.
5. Нативный observer собирает TB edge coverage после двух событий: `RESUME 2`, подтверждающего продолжение после удаления Phase 1, и первого успешного `read`/`pread64` выбранного файла. Предшествующая распаковка, паузы контроллера и busy loop до чтения не входят в карту. Переходы после чтения учитываются во всём гостевом процессе, без утверждения об идеальной границе OEP.
6. После нормального завершения QEMU закрывается карта с заголовком завершённости. Worker требует успешного retirement, результата капсулы, подтверждённой очистки cgroup и корректной карты. Контроллер завершает очистку попытки и передаёт ровно 65 536 байт bridge. Только эта карта попадает в AFL SHM.
7. AFL++ классифицирует счётчики и сохраняет интересный вход в `afl/default/queue`. При новой мутации весь цикл повторяется с чистым rootfs и новым исходным ELF.

Например, seed `A` проходит одну ветвь контролируемого payload. Мутация в `B` проходит другую; новая карта заставляет AFL++ сохранить `B`. Следующая попытка снова получает базовое содержимое файловой системы, даже если предыдущая создала `/tmp/afl-marker`.

## Состав реализации

| Файл | Ответственность |
|---|---|
| `experiments/afl_file/bridge.c` | Forkserver, AFL SHM, передача дескриптора и байтов входа |
| `experiments/afl_file/coverage.h` | Карта гостевых TB-переходов, NeverZero-счётчики, отслеживание открытия и чтения файла |
| `experiments/retirement_observer/observer.c` | Включение сбора в состоянии `RESUME 2`, callbacks QEMU |
| `taintforge_env/afl_file.py` | Подготовка кампании, привязки SHA-256, снимки rootfs, отдельная попытка, проверка карты |
| `taintforge_env/afl_transport.py` | Последовательные worker-процессы, сроки исполнения, остановка и очистка |
| `taintforge_env/input_retirement.py` | Включение файловой привязки в существующий контракт, создание и сохранение карты |
| `scripts/run_afl_file.py` | CLI `prepare` и `run` |
| `scripts/verify_afl_components.py` | Проверка реальных AFL++ и QEMU без заявления о прохождении M4 |
| `scripts/verify_afl_file_e2e.py` | Полная проверка контролируемого ELF через M4 на подходящем хосте |

Формат карты: 64-байтовый заголовок `TFACOV1`, версия, размер, флаги начала/завершения, число блоков и первый/последний PC; затем bitmap 64 KiB. Хеш карты сохраняется отдельно. Перенос, изменение размера, пустая или незавершённая карта блокируют успешную попытку.

## Границы MVP

- Тот же профиль входного ELF, что у M3/M4: статический little-endian i386 ET_EXEC; один процесс и один vCPU. ELF64, PIE, динамические ELF и дочерние процессы этим профилем не поддерживаются.
- Один заранее выбранный абсолютный гостевой путь. Поддерживаются i386 `open`, `openat` с абсолютным путём, `read`, `pread64`, `close`. `dup`, передача FD, относительные имена и чтение через `mmap` пока не отслеживаются. Отслеживается один последний открытый FD этого файла.
- Чтение должно произойти после retirement. Если программа прочитала файл только до retirement, сбор не начнётся, попытка будет отклонена с ошибкой отсутствия полного покрытия.
- Вход 1..4096 байт по умолчанию, настраиваемый предел до 1 MiB. Seeds фиксируются копированием в кампанию. Путь executable, symlink/hardlink и служебные `/proc`, `/sys`, `/dev`, `/__taintforge*` запрещены.
- Сеть выключена. Новых источников из сетевых ответов и переменных окружения нет. DSE-код не меняется и не подключается к выбору входов. Интерфейсов replay и нового oracle нет.
- Это база поиска новых путей. Результаты непрошедших проверку капсул, аварии QEMU и транспортные ошибки не объявляются падениями malware: forkserver останавливает кампанию. Обычные проверенные guest exit codes сохраняются в `result.json`, но bridge возвращает AFL успешное завершение. Классификация целевых crashes/hangs и их воспроизведение отложены вместе с oracle/replay.
- Нет persistent mode, восстановления кампании или снимков памяти после распаковки. Подготовка и распаковка повторяются на каждый вход. Скорость компонентного теста не характеризует скорость полного M4.
- Унаследованные свойства M4 остаются явно записаны: `protected_control_channel=false`, `hostile_sample_ready=false`. Новая интеграция не делает отдельного доказательства защиты памяти от враждебного гостя в адресном пространстве QEMU.

## Установка дополнения

В архиве находятся полные версии новых/изменённых файлов, patch и установщик. База — `taintforge_m4_phase1_integration_v1/source`. Установщик сравнивает SHA-256 существующих файлов перед любыми заменами, отказывается затирать несовпадающие локальные изменения и сохраняет резервные копии заменяемых файлов. Коммитов и push нет.

```bash
unzip taintforge_afl_file_mvp_v1.zip
python3 taintforge_afl_file_mvp_v1/apply.py --repo "$HOME/taintforge"
```

## Полная проверка на Arch-хосте

Нужны AFL++, GCC/binutils с ASan/UBSan, Python 3.12+, pkg-config, GLib, Capstone, Z3, QEMU 11.0.1 с плагинами API 6 и уже работающий M4: systemd, cgroup v2, sudo, разрешённые mount/PID/network namespaces. Используется тот же pinned SDK, что лежит в репозитории.

```bash
cd "$HOME/taintforge"
bash scripts/build_run_afl_file.sh \
  "$HOME/.local/opt/taintforge/qemu-11.0.1/bin/qemu-i386" \
  "$HOME/taintforge/workdir/afl-file-host-check" \
  /usr/bin
```

Каталог результата должен быть новым. Скрипт запускает тесты, собирает существующую Phase 1 без изменения её исходников и проверяет controlled ELF через настоящий M4. Проверяются три различных пути, повторяемость карты `A`, уникальность попыток, восстановление файла из baseline, отсутствие маркера в baseline, retirement, очистка cgroup и рост очереди AFL. Результат: `e2e/acceptance.json`. При недоступном M4 этот тест завершается ошибкой; компонентной подмены в нём нет.

Короткая компонентная проверка отдельно:

```bash
cd "$HOME/taintforge"
python3 -m scripts.verify_afl_components \
  --qemu "$HOME/.local/opt/taintforge/qemu-11.0.1/bin/qemu-i386" \
  --afl-bin /usr/bin \
  --out "$HOME/taintforge/workdir/afl-file-components" \
  --seconds 15
```

Она исполняет безвредный статический i386 ELF, использует настоящие AFL++/forkserver/QEMU, реальные rootfs snapshots и тот же код карты. Сбор включён после чтения файла сразу, без Phase 1: поэтому `m4_end_to_end_verified=false` записывается явно. Дополнительно проверяются одинаковые карты для разных входов у программы, игнорирующей их содержимое, ошибка worker без ложного crash и остановка worker при потере AFL child.

## Кампания для своего ELF

Подготовь непустые seeds и выбери абсолютный путь, который ELF открывает после retirement. Если файл уже есть в базовом rootfs, подготовка откажется его перезаписывать: для текущего CLI нужен свободный путь. Ниже используется контролируемый пример с `/etc/afl-input`; для своего ELF передай его реальный входной путь.

```bash
cd "$HOME/taintforge"
python3 -m scripts.run_afl_file prepare --mode fresh \
  --binary "$HOME/taintforge/workdir/afl-file-host-check/e2e/fixture/guest-i386" \
  --qemu "$HOME/.local/opt/taintforge/qemu-11.0.1/bin/qemu-i386" \
  --plugin "$HOME/taintforge/workdir/afl-file-host-check/build/libtaintforge_ir.so" \
  --seeds "$HOME/taintforge/workdir/afl-file-host-check/e2e/seeds" \
  --guest-file /etc/afl-input \
  --out "$HOME/taintforge/workdir/afl-file-campaign" \
  --max-input 4096
python3 -m scripts.run_afl_file run \
  --out "$HOME/taintforge/workdir/afl-file-campaign" \
  --afl-bin /usr/bin --seconds 300 --executions 64
```

Не добавляй `-Q`: гостевое исполнение уже выполняет TaintForge. AFL++ управляет обычным native bridge, а не самостоятельно запускает свой QEMU backend.

## Артефакты и остановка

`campaign.json` содержит состояние кампании, исходные хеши, лимиты и команду AFL. `afl.log` — вывод AFL; `afl/default/fuzzer_stats` — статистика; `afl/default/queue` — сохранённый корпус. Каждая `cases/NNNNNNNN` содержит вход, worker log, карту, `result.json` завершившегося worker, `transport.json` и полную отдельную сессию TaintForge. Для отменённой до завершения попытки `result.json` может отсутствовать; статус отмены и подтверждение очистки записаны в `transport.json`.

Ctrl+C останавливает AFL и worker. При необходимости контроллер останавливает только systemd unit с nonce, привязанным к этой попытке. Следующая попытка не начинается до очистки предыдущей. Инфраструктурная ошибка прекращает кампанию, а не пополняет каталог crashes.

Проверки и их фактические результаты в среде разработки перечислены в `validation/verification.json` поставляемого архива. Успешная компонентная проверка не заменяет `e2e/acceptance.json` с твоего M4-хоста.
