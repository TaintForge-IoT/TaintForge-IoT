# M3: статический ELF, удаление Phase 1 и повтор после ремонта

Обновление 12 октября 2026: расширена приёмочная матрица. Полная приёмка M3 остаётся открытой до нового прогона на QEMU 11.0.1/systemd. Предыдущие доказательства retirement и обеих попыток repair проверены отдельно; их результат не распространяется автоматически на новые сценарии.

## Исполнение

`run --retire-phase1 --binary FILE` принимает статический little-endian i386 ET_EXEC до 64 МиБ, без PIE/PT_INTERP/PT_DYNAMIC. Сеть — `none`, один процесс/vCPU. Native observer запрещает fork/clone/exec и второй vCPU.

Каждая попытка получает исходный ELF, отдельные QEMU/rootfs, attempt contract, analysis ID и nonce. Phase 1 выбирает эвристический кандидат; контроллер проверяет verdict и экспорт, сохраняет экспорт и выдаёт связанный с ним permit. После uninstall/release проверяются живые maps процесса, отсутствие модуля Phase 1 и продолжение исполнения под observer. Прикладную цель отдельно оценивает Phase 2.

Ненулевой exit приложения после подтверждённого retirement может привести к ремонту окружения и новой попытке с исходного ELF. В тесте repair создаётся отсутствующий родительский каталог для `open(..., O_CREAT)`. Неизвестное содержимое файлов не выдумывается. Неполное доказательство удаления/продолжения блокирует финализацию и повторное использование попытки.

OEP остаётся эвристическим: `oep_proven=false`, `exact_oep_cutover=false`. Полного checkpoint и восстановления CPU/памяти нет. Обычный неупакованный статический ELF может не дать кандидата. Защита от враждебного гостя, M4/M5 и anti-VM не входят в это обновление.

## Матрица 2

| Сценарий | Проверка |
| --- | --- |
| normal | Исходный тестовый код, exit 0, цель достигнута. |
| repair | Exit 42/ENOENT → подтверждённое создание каталога → свежая попытка, тот же ELF, exit 0. |
| relocated-branch | Другой код копирования/ветвления, база `0x09000000`, OEP `0x09004000`. |
| page-offset | Обратное копирование, внутренний call/ret, база `0x0b000000`, OEP `0x0b004100`. |
| missing-verdict | Native отказ 89, неуспешная финализация, resume без новых исполнений. |
| fork-after | Native guard 126, неуспешная финализация, resume без новых исполнений. |

Это шесть сценариев, семь попыток и пять положительных portable evidence. Три положительных исходника отличаются телом и адресами. Символы удаляются до запуска; адреса, извлечённые до strip, использует только приёмочная проверка после исполнения. Контроллер выбора OEP их не получает.

Во всех случаях проверяются отсутствие fallback kill и пустое дерево процессов. Для repair дополнительно проверяются квитанция применения, хеши входного плана/requirements и новая версия manifest. Для отказов сохраняются исходный отчёт, execution claim и отдельный отчёт resume.

## Файлы обновления

- `experiments/input_retirement/branch.S`, `offset.S`, `cases.py`: новые ELF и сборка матрицы.
- `scripts/run_input_retirement_e2e.py`: шесть сценариев и проверка их доказательств.
- `scripts/run_input_retirement_tests.py`: полный набор из 107 методов, машинный результат; пропуски не считаются успехом.
- `scripts/collect_input_retirement_evidence.py`: архивирование ограниченного набора доказательств, хеши, повторная проверка portable evidence; неполный прогон остаётся неполным.
- `scripts/build_run_input_retirement.sh`: сохранение журналов каждого этапа и автоматическая сборка архива при выходе.
- `tests/test_input_retirement_matrix.py`, `test_input_retirement_collection.py`: девять новых проверок.

Отдельный `cleanup-comments.patch` сокращает комментарии/docstrings старого capsule/retirement-кода. Исполняемые Python AST и C-токены сохраняются. `phase1_runtime.py`, включая проверенный вариант `flags_receipt`, не меняется. После обновления нужен новый каталог прогона; существующие сеансы связаны с хешами исходников.

## Запуск и результаты

```bash
cd "$HOME/taintforge-m3-matrix-v1"
bash scripts/build_run_input_retirement.sh
```

Скрипт использует `$HOME/.local/opt/taintforge/qemu-11.0.1/bin/qemu-i386`. Можно передать путь к QEMU и новый каталог результатов двумя аргументами. Нужны прежние зависимости сборки, systemd/cgroup v2 и sudo. Сборка плагинов выполняется заново.

В каталоге прогона: `validation/` с логами и `tests.json`, `e2e/report.json`, `acceptance.tar.gz` и `acceptance.tar.gz.sha256`. Архив содержит receipt ремонта, claims, исходные и resume-отчёты, журналы ресурсов/сервиса, конфигурацию и portable evidence. Это выбранные доказательства, не полная резервная копия rootfs/сеанса. SHA-256 проверяет целостность, но не удостоверяет автора данных.

При ранней ошибке сохраняется частичный архив с `complete=false`; код ошибки не превращается в успех. Завершённость архива ещё не означает независимую приёмку M3.

Локальные результаты этой поставки и ограничения среды перечислены в `validation/summary.json` пакета. Полный native/systemd-прогон новой матрицы здесь не заявляется пройденным.
