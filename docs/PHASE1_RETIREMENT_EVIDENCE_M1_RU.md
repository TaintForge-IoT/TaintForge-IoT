# Переносимые доказательства retirement, M1

Дата: 6 октября 2026. Ветка: `phase1-retirement-evidence-m1`. Основа — v2, коммит `903accdf2f7e209f951f86bb54c190c5246b0991`.

M1 исправляет проверку сохранённых свидетельств и диагностику запуска. Приёмка v2/M1 на целевом стенде всё ещё требуется. Нативная Phase 1, алгоритм OEP, протокол permit и асинхронный uninstall этим патчем не изменяются. Произвольные ELF, строгая изоляция и анти-VM не добавляются.

**Проблема и исправление**

Ранее финализатор сравнивал старый `/proc/<pid>/maps` с текущим inode `.so`. После копирования файлов проверка отказывала. Теперь live observer сохраняет `mapping-identity.json` с версией схемы, identity/nonce попытки, PID/starttime и двумя модулями: phase1/observer. Для каждого сохраняются device/inode, размер и SHA-256; отдельно фиксируются build ID Phase 1 и хеш sidecar. В каждой контрольной точке сохраняются maps и исходный `/proc/<pid>/stat`, а их хеши и хеш identity входят в журнал наблюдений.

Во время исполнения observer проверяет текущие файлы и отображения. Между двумя точками их live identity должна оставаться той же. После исполнения maps сопоставляются с записанными device/inode; байты сохранённых модулей сверяются по размеру/хешу и sidecar. Новые inode копии не участвуют в исторической проверке.

Вторая зависимость — абсолютные пути capture manifest. Их нельзя переписать: его исходный хеш входит в выданный permit. Новый необязательный параметр `Phase1Run.verify(recorded_directory=...)` позволяет сверять записанный путь с исходным каталогом, одновременно читая байты только из текущего каталога. Без этого параметра прежняя точная проверка пути сохранена. Manifest, export и permit в переносимом комплекте остаются побайтно исходными.

**Комплект доказательств**

`taintforge_env/retirement_evidence.py` создаёт каталог со схемой `taintforge-retirement-evidence`, версия 1. Он содержит исходные bindings, нормализованные bindings для локального чтения, точные модули/sidecar, события, карты/stat, результат supervisor, stdout/trace, исходный и сохранённый экспорт. `bundle.json` перечисляет относительные пути, размеры и SHA-256 файлов; неизвестные файлы, дубли, выходы за каталог, symlinks и нарушение бюджета отвергаются. Ограничения: до 64 файлов, 1 ГиБ на файл и 2 ГиБ суммарно. Это границы упаковщика, а не новый общий бюджет памяти Phase 1.

Проверка не запускает QEMU, не загружает `.so` и не обращается по историческим абсолютным путям. Она проверяет целостность и заново выполняет семантическую проверку retirement. Разрешён ожидаемый отказ: комплект может быть `verified`, но `attempt_outcome=aborted` и `phase1_retired=false`. Это не успешная выгрузка.

Хеш манифеста комплекта возвращается упаковщиком и записывается в итоговый suite report. При передаче комплекта сохраняйте этот хеш отдельно и передавайте в `verify --expected-sha256`. Без внешнего доверенного хеша проверяется внутренняя согласованность, а не аутентичность. Изменение всего комплекта вместе с его собственным manifest не защищено подписью. `authenticity=not_asserted`, `protected_control_channel=false` остаются честными ограничениями.

Scope комплекта — retirement. Он не заменяет проверку всего session bundle, бинарника QEMU, cgroup, rootfs или хостовой изоляции. Исходные проверки unified finalization и ресурсов сохранены отдельно.

**Совместимость старых данных**

Новые попытки имеют `retirement_evidence_schema=1`. Отсутствие обязательного identity в таком запуске — ошибка. Старый запуск без новой схемы/identity получает `EvidenceInconclusive`: нужные наблюдения отсутствуют, требуется повторный запуск. Команда упаковки возвращает JSON со статусом `inconclusive` и код 2. Исторические результаты не дополняются выдуманной live identity. Повреждённый новый комплект получает `failed`, код 1. Успешная проверка — код 0.

**Диагностика запуска**

Создание сокета observer перенесено внутрь обрабатываемой секции. Оба worker при ошибке до `ready` сначала сохраняют причину, затем передают её родителю. Сохраняются component, stage, exception type, errno и сообщение. Родитель различает startup failure, execution timeout, unexpected guest failure и evidence failure; runtime-ошибки worker также доступны в `controller_failures`. Ошибки peer identity/экспорта остаются отказами протокола, их проверки не выключаются.

Ошибки socket/bind больше не скрываются за безымянным `EOFError`. Реальный EOF без сообщения и deadline готовности также имеют отдельную причину. Preflight failure записывается в supervisor report до запуска QEMU.

**Запуск**

После установки в отдельную рабочую копию:

```bash
bash scripts/build_run_phase1_retirement_evidence.sh
```

По умолчанию используется `$HOME/.local/opt/taintforge/qemu-11.0.1/bin/qemu-i386`. Создаются новая сборка, каталог `workdir/phase1-retirement-evidence-e2e-*` и подкаталог `retirement-evidence` в каждом сценарии. Сводный `report.json` должен содержать 12 принятых случаев, `dynamic_trigger_verified=true`, `runtime_unchanged=true`, проверенные `portable_evidence`; прежние проверки `tree_empty` и `resume_blocked` сохраняются. Для отдельного сохранённого запуска CLI предоставляет `pack --run-dir ... --out ...`; для готового комплекта — `verify DIRECTORY --expected-sha256 HASH`.

Автоматические проверки нового переносимого формата используют явно синтетический executor и не доказывают свежий QEMU-run. Тест переноса удаляет исходную рабочую директорию, проверяет изменение inode и успешную проверку неизменного комплекта. Приёмка реальных live capture и unified/systemd/cgroup выполняется отдельно на целевом стенде; старые 14 QEMU-запусков v2 нельзя объявлять проверкой M1.

**Проверено при подготовке M1**

61 тест прошёл без пропусков: 48 существующих и 13 новых. Включены нативные проверки протокола, вердикта и очистки; для проверок владельцев использованы ASan/UBSan, LeakSanitizer отключён (`TF_RETIRE_LSAN=0`). Синтетические integration-тесты не выдаются за запуск QEMU.

Одна настоящая попытка старта локального безвредного fixture остановилась до запуска QEMU: среда запретила создание Unix socket (`EPERM`). Новый отчёт сохранил `category=startup_failure`, `component=permit`, `stage=socket`, `errno=1`; QEMU не стартовал. Новый полный QEMU/unified suite здесь не принят. Старый реальный отчёт v2 корректно получает `inconclusive`, код 2. Все 56 исходных файлов нативной сборки совпадают с v2.

При итоговой регрессии обнаружили обращение старого синтетического executor к `phase1_retirement.maps`; совместимый импорт сохранён, итоговый прогон повторён успешно.
