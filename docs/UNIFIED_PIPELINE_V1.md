# Общий запуск фаз 1 и 2, версия 1

Новая команда `scripts/run_unified_pipeline.py` запускает исходный ELF с
плагином анпакера внутри `PrebuiltRootfsRunner` и существующего
`EnvironmentSynthesisLoop`. Профиль: Linux i386, один гостевой процесс и поток;
хост Linux x86 с glibc. Файлы фазы 1 не изменяются.

## Что происходит в одной попытке

1. По заголовкам исходного ELF определяется архитектура, `PT_INTERP` и
   рекурсивный набор `DT_NEEDED`. Образец на этапе подготовки не исполняется.
2. В seed rootfs копируются исходный файл, подходящий гостевой загрузчик и
   библиотеки. Создаются минимальные каталоги и настройки DNS из явной политики.
3. Отдельно собирается набор исполняющих средств: динамический `qemu-i386`,
   выбранный плагин с его `.runtime.json`, хостовый загрузчик и библиотеки QEMU.
4. Сессия связывается с хешами образца, среды, сетевой политики, ReplayStore,
   набора QEMU/плагина и кода анализатора. Для попытки создаётся свежая rootfs.
5. В namespaces runner запускает **один QEMU с плагином с первой инструкции**.
   Распаковка, обращения к окружению и продолжение payload происходят в этом
   исполнении. Выбор OEP не вызывает повторный `exec`, загрузку дампа или смену PC.
6. После завершения проверяется публикация артефактов фазы 1. История кандидатов
   проецируется в `AttemptResult`; наблюдения syscalls и ремонты обрабатываются
   существующей фазой 2. После ремонта новая попытка снова запускает исходный ELF.

Это подключение инструментации и артефактов к общему исполнителю. Переключение
инструментации во время исполнения, остановка на boundary и forkserver сюда не
входят. Переходы стадий в AttemptResult записываются после чтения событий попытки.

## Зависимости и первая проверка

Нужны применённые пакеты Phase 1 runtime v1 и DNS/UDP, Python 3.11+, собранный
плагин с действительным sidecar, совместимый динамический QEMU с поддержкой
плагинов, а также обычные зависимости prebuilt runner: sudo, unshare, mount,
chroot, ip, timeout, bash. Для сетевых режимов нужны зависимости существующего
сетевого backend, включая iptables. Сборка анпакера остаётся у разработчика фазы 1.

По умолчанию ищутся `build/libtaintforge_ir.so` и `qemu-i386` в PATH. При другом
размещении укажите `--plugin /путь/plugin.so --qemu /путь/qemu-i386`.

Приёмка на VM, только на контролируемом примере из пакета фазы 1:

```bash
sudo -v &&
PYTHONPATH=. python scripts/run_unified_local_e2e.py \
  --out "workdir/unified_e2e_$(date +%Y%m%d_%H%M%S)"
```

Сценарий собирает пример двумя командами `as`/`ld`, запускает его в двух свежих
сессиях и проверяет: настоящий startup плагина, целостность публикации, выбор и
инвалидацию кандидатов, сохранённый stack marker, конечный вывод, историю стадий,
раздельные идентификаторы и удаление mountpoints. JSON из stdout гостя не
используется как событие анализатора. Успех этого режима относится к static i386.

Для дополнительной приёмки **dynamic i386**:

```bash
sudo -v &&
PYTHONPATH=. python scripts/run_unified_local_e2e.py \
  --out "workdir/unified_dynamic_e2e_$(date +%Y%m%d_%H%M%S)" \
  --dynamic-sysroot /
```

В выбранном sysroot должен быть `/lib/ld-linux.so.2` архитектуры i386. Если он
находится в отдельной файловой системе прошивки/SDK, передайте её корень вместо
`/`. Динамический пример вызывает функцию через PLT; библиотека вызывает вторую
библиотеку и возвращает проверяемое значение, затем выполняются два слоя
распаковки. Для сборки нужны gcc с генерацией i386, as и ld; libc development
headers для этих конкретных контрольных библиотек не нужны.

## Запуск образца

```bash
sudo -v &&
PYTHONPATH=. python scripts/run_unified_pipeline.py run \
  --binary /absolute/path/sample.elf \
  --out workdir/unified_sample_001 \
  --sysroot /absolute/path/compatible_sysroot \
  --network none --timeout 60 --max-steps 1
```

`--sysroot` по умолчанию `/`; статическому ELF загрузчик и библиотеки не нужны.
Выходной каталог должен быть новым. Для подготовки без исполнения добавьте
`--prepare-only`. Продолжение использует уже сохранённые настройки:

```bash
PYTHONPATH=. python scripts/run_unified_pipeline.py resume \
  --out workdir/unified_sample_001 --max-steps 1
PYTHONPATH=. python scripts/run_unified_pipeline.py status \
  --out workdir/unified_sample_001
PYTHONPATH=. python scripts/run_unified_pipeline.py verify \
  --out workdir/unified_sample_001
```

`resume` не исполняет повторно уже использованную rootfs. Завершённая сессия не
создаёт новую попытку только из-за повторного вызова команды. При изменении
связанных файлов или после неразрешённого сбоя нужен разбор причины, а не
удаление execution claim. Для другого эксперимента создайте новую сессию.

Сеть подключается через прежние `controlled`, `record`, `replay`. Для них
обязателен `--network-policy /путь/network_policy.json`; для replay также
`--replay-store /путь/replay_store`. Неизвестные адреса не получают автоматического
разрешения на upstream. Guest resolv.conf берёт первый DNS endpoint политики;
`--dns-server` выбирает другой явно разрешённый IPv4 endpoint порта 53.
Режим record сохраняет capture; импорт в replay bundle остаётся отдельной
существующей операцией. Общий launcher не запускает автоматический live record
перед анализом и не расширяет политику по результату DNS.

## Динамические ELF и восстановление заголовков

Для **первого запуска исходного ELF** и **продолжения того же процесса** после
распаковки восстановление заголовков не требуется. Загрузчик уже создал процесс;
память, стек, дескрипторы и обработанные релокации продолжают использоваться.
Новый код подготавливает `PT_INTERP`, рекурсивные `DT_NEEDED` и гостевой library
path. Он проверяет архитектуру каждой зависимости и разрешает абсолютные
symlinks относительно выбранного sysroot, без подстановки файлов из хостового `/`.

Дополнительные пути указываются как `--library-dir /opt/vendor/lib` **внутри
sysroot**. Путь передаётся гостю посредством QEMU `-E LD_LIBRARY_PATH=...`, не
хостовому загрузчику QEMU. Для библиотек, которые программа открывает через
`dlopen`, доступен `--extra-library libvendor.so`. Модули glibc `libnss_files` и
`libnss_dns` включаются, если они есть в sysroot; прочие dlopen-зависимости не
угадываются. Подбор правильной версии ABI остаётся ответственностью выбранного
sysroot: совпадение архитектуры не доказывает совместимость версий символов.

**Отдельный исполняемый файл из `unpacked.bin` пока не восстанавливается.** Дамп
фазы 1 содержит только отслеживаемые страницы и может быть частичным. Помимо
ELF header понадобятся согласованные program headers, `PT_LOAD`, интерпретатор,
`PT_DYNAMIC`, символы/строки, релокации, TLS и информация об адресах загрузки.
Установка `e_entry = OEP` и копирование старого заголовка этого не обеспечивают.
Raw dump не принимается как исходный ELF общего launcher.

Следующий блок реконструкции должен принимать карту регионов и поколений кода
с происхождением, проверять полноту памяти и динамических структур, формировать
новый файл без перезаписи исходника и доказывать его запуск в отдельной чистой
попытке. При нехватке данных результат должен быть `unsupported/incomplete`.
Это отдельный режим, не неявная замена естественного продолжения процесса.

## Артефакты и границы результата

В `unified_report.json` находятся результат сессии, код гостя и сводка фазы 1.
Полная попытка хранится в `session/iterations/0000/run/`:

- `config/guest_runtime.json`: исходный ELF, загрузчик, библиотеки и их хеши.
- `config/analyzer_runtime/bundle.json`: отдельный набор QEMU/плагина.
- `config/phase1_binding.json`: session/attempt/analysis identity и пути публикации.
- `logs/phase1/`: исходные events, manifest, dump, report, IR.
- `config/phase1_result.json`: проверка целостности и проекция стадий.
- `logs/qemu_strace.log`, `logs/runtime_stdout.log`, `logs/runtime_stderr.log`:
  syscalls, вывод гостя и диагностика анализатора.

Выбор кандидата означает `oep_validation`, а не доказанный OEP. При инвалидации
проекция возвращается к поиску; `profile_lost` прекращает доверенное продвижение
истории. `oep_proven` и `fuzzing_ready` остаются false. Timeout без committed
manifest сохраняет полный префикс событий с `artifact_integrity=incomplete`;
повреждённая committed публикация является ошибкой. Если плагин не загрузился,
успех guest exit не подменяет подтверждение startup анализатора.

QEMU/плагин и гостевые библиотеки размещаются раздельно. Это **не защита памяти**:
QEMU и плагин остаются одним хостовым процессом, канал артефактов — обычными
файлами, а существующий sandbox не превращается в hardened malware appliance.
Execution Capsule + Memory Provenance + Residue Oracle остаются следующим
блоком: отдельное состояние анализатора, учёт владельца/происхождения каждой
области и проверка оставшегося состояния перед повторением входа. Точка reset,
строгий защищённый канал, внешняя запись гостевой памяти и первая кампания
фаззинга в этот интеграционный пакет не входят.

Изменения проверяются unit/integration tests с явно синтетическим исполнителем,
реальным запуском контрольного host ELF через подготовленный динамический
загрузчик и сборкой i386 fixtures. Проверка настоящего QEMU, плагина и namespaces
в этой среде недоступна; её выполняет приведённый выше VM acceptance script.
