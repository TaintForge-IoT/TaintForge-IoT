# DTA-guided file corpus, first stage

`python3 -B -m scripts.generate_dta_corpus --help` describes the offline CLI.
It consumes an immutable seed, its target ELF, one diagnostic trace and the
exact file path recorded by the plugin. It executes no target and calls no solver.

The trace must come from a separate analysis run with `runtime-log=roots` and
Phase 1 active through the payload's file read and conditional branches. The
warm AFL checkpoint retires Phase 1 before input consumption, so its retirement
trace is not a payload DTA trace. The normal Phase1Run adapter intentionally
still permits only `runtime-log=summary`; this change does not widen that policy.

The parser binds the existing `BRANCH-PROV`, `BRANCH-ROOT` and `DCFG-JCC` records.
It selects branches whose data roots are complete, carry no incomplete reasons,
and all refer to the selected file. Address roots, unrelated files and semantic
roots cannot independently select mutable file bytes. Conflicting identities,
missing selected DCFG evidence and exceeded budgets stop publication.

The generator mutates the selected bytes independently and as dependency groups.
It uses a fixed boundary-value palette, observed-byte neighbours and bit flips.
It preserves length, includes the original seed, and deduplicates by SHA256.
Repeated dependency groups are mutated once. The first profile supports seeds
of 1–4096 bytes, at most 4096 candidates, and at most 64 MiB of generated bytes.
Defaults are 128 candidates, 64 branch sites and 16 offsets per site.

The new output directory contains `seeds/`, with only binary files named by
SHA256, and `manifest.json`. The manifest records target/seed/trace identities,
branch sites, exact edits, exclusions, budgets and explicit result scope.
The CLI requires a new output directory and does not overwrite existing results.

## Handoff to the fuzzer

The teammate can consume the generated `seeds/` directory through the existing
seed import API. Candidate generation is independent of AFL and warm execution.
The fuzzer should replay candidates and retain inputs that add observed coverage
or another explicitly selected objective. The offline manifest does not claim
that a candidate changes a branch or adds coverage.

The seed/trace association is supplied by the caller. Hashes bind the supplied
files but do not independently authenticate their execution relationship. These
stderr diagnostics are hints, not a proof format; do not treat them as trusted
input-origin evidence for solver or OEP proofs. No magic constants or dictionary
entries are inferred from taint alone.

## DSE extension

Sites retain the PC, vCPU, occurrence, event and sequence. `source_block_generation`
is explicitly the source basic block's generation, not the branch instruction's
generation. The diagnostic format lacks exact branch bytes and producer IR;
sites therefore carry `dse_eligible=false` and `dse_status=NOT_RUN`.

A later analysis worker can recapture a selected site with exact instruction
origin, register its offsets through `concolic_environment.EnvironmentFile`,
solve the selected predicate and validate the full candidate through the existing
concrete rerun checks. A DTA proposal must never be promoted to VERIFIED merely
because a solver returned SAT. Stdin and network input require their own source
binding and collection routes.
